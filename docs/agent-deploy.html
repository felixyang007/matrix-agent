🤖 Matrix Agent 部署指南

把你的 Mac 变成一台「远程设备机」——插上手机，团队就能在网页上远程控制真机、跑自动化测试。

⏱ 约 15 分钟💻 Mac / Linux 通用🧑‍💻 无需编程基础🍎 可选 iOS 模拟器

所有命令都可以直接复制，粘贴到「终端」App 里按回车。右上角的「☑ 完成」可以打勾记录进度（自动保存）。

准备① Java② 下载③ 配置④ 启动⑤ 接设备🍎 iOS 模拟器出问题了？日常维护
🧰

开始前：准备好这 4 样东西

  1. 一台 Mac 或 Linux 电脑（会一直开着、插着测试手机的那台）
  2. 测试手机 + 数据线（Android 真机；质量好的线，别用扩展坞）
  3. 服务器地址（形如 10.2.3.9:3000，找管理员要，就是你们平时打开测试平台的网址）
  4. Agent Key（管理员在平台「设备中心 → Agent 中心 → 新增」里生成的钥匙，一串字母数字）
💡 不用准备：不需要管理员密码、不需要装数据库——Agent 是个绿色软件，解压即用。
1

装 Java 17（Agent 的运行环境）

打开「终端」App（Command+空格 搜 终端 或 Terminal），粘贴下面命令回车：

java -version

看第一行输出：

openjdk version "17.x.x" … ✅ 显示 17 或更高 → 跳到第 2 步 command not found: java → 继续往下装

没装的话，用 Homebrew 安装（两段分别复制执行；若提示没有 brew，先到 brew.sh 照首页一句命令装好再回来）：

brew install openjdk@17
sudo ln -sfn /opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk-17.jdk
⚠️ 第二条命令会要你的开机密码（输入时屏幕不显示，正常），回车即可。

装完再跑一次 java -version，看到 17 就 OK。

2

下载 Agent 包并解压

先确认你的 Mac 芯片类型（决定下载哪个包）：

uname -m
arm64 → Apple 芯片（M1/M2/M3/M4） x86_64 → Intel 芯片

到团队发布页下载 macosx_arm64 结尾的 zip：
👉 github.com/felixyang007/matrix-agent/releases（需要团队 GitHub 权限；也可以直接用管理员发你的 zip，都一样）

假设下载到了「下载」文件夹，解压到家目录并改个好记的名字：

unzip -q ~/Downloads/*macosx_arm64.zip -d ~ && mv ~/sonic-agent-* ~/matrix-agent 2>/dev/null || mv ~/*macosx_arm64 ~/matrix-agent
ls ~/matrix-agent

到团队发布页下载 macosx_x86_64 结尾的 zip：
👉 github.com/felixyang007/matrix-agent/releases（需要团队 GitHub 权限；也可以直接用管理员发你的 zip，都一样）

假设下载到了「下载」文件夹，解压到家目录并改个好记的名字：

unzip -q ~/Downloads/*macosx_x86_64.zip -d ~ && mv ~/sonic-agent-* ~/matrix-agent 2>/dev/null || mv ~/*macosx_x86_64 ~/matrix-agent
ls ~/matrix-agent

解压后目录里应该有这几样（最后一条命令的输出）：

sonic-agent-macosx-arm64.jar config/ plugins/ mini/ ✅ 齐了
💡 这个目录后面统称 ~/matrix-agent。想放别处也行，后面命令里的路径跟着改就好。
3

填配置（唯一要动脑的一步）

下面生成器里填 3 个值，右侧配置会实时生成，点复制按钮，然后整段粘贴进配置文件。

✅ 推荐：只有你自己在这台 Mac 的浏览器里看设备。永远不受换 Wi-Fi 换 IP 影响，零维护。


  


  
把配置写进文件（一条命令搞定，不用学编辑器）：

  
cat > ~/matrix-agent/config/application-sonic-agent.yml <<'EOF'
EOF

  
⚠️ 上面命令里已自动带入你填的值。先在生成器里把 3 项填完，再复制这条命令执行。

  
💡 选了「团队任何人都能看」？还需要在路由器后台把你 Mac 的 IP 做 DHCP 保留（钉死 IP），否则 Mac 换网络后别人会连不上画面。不会弄就先选「只有我自己」。







  
4
启动 Agent

    

  
复制执行（Apple 芯片版；Intel 机器把 jar 名换成 sonic-agent-macosx-x86_64.jar，或直接输入 sonic-agent- 后按 Tab 键自动补全）：

  
cd ~/matrix-agent
nohup java -Dfile.encoding=utf-8 -Dspring.profiles.active=sonic-agent \
  -jar sonic-agent-macosx-arm64.jar > agent.log 2>&1 &
disown

  
等 10 秒左右，然后验证（关键！）：

  
grep -E "server auth successful|Enable Android Module" agent.log

  
… INFO … server auth successful!   ✅ 连上服务器了！
… INFO … Enable Android Module      ✅ 安卓模块已加载！

  
两条都出现 = 成功。打开测试平台网页 →「设备中心 → Agent 中心」，你那台 agent 应该是在线状态。

  
⚠️ 没出现？→ 页面底部「出问题了？」第 1 条。







  
5
插上手机，完成！

    

  
    
    
  1. 手机：设置 → 关于手机 → 连点「版本号」7 次打开开发者模式 → 设置 → 系统 → 开发者选项 → 打开「USB 调试」
    2. 
    
  2. 数据线插手机 ↔ Mac，手机上弹出「允许 USB 调试吗？」→ 勾选 一律允许 → 允许
    3. 
    
  3. 验证（在终端跑）：
    4. 
  

  
~/matrix-agent/plugins/adb devices -l

  
List of devices attached
ABC123XYZ      device product:… model:…    ✅ 认到了（状态必须是 device）
ABC123XYZ      unauthorized               → 看手机屏幕，点掉授权弹窗

  
等十几秒，平台网页「设备中心」里你的手机就会变在线 🎉 点「远程控制」试试——能看到画面、能用鼠标操控，就全部完成了。

  
💡 模拟器也行：Android 模拟器（Android Studio）开起来等同真机，自动识别；iOS 模拟器（Xcode 自带）见下方 🍎 iOS 模拟器 一节。

  
🎉 部署完成！现在你可以：网页远程控制真机 / 跑自动化用例 / 给团队成员分配这台设备。往下翻有「日常维护」和「出问题了？」两节，建议收藏本页。







  
🍎
进阶：接入 iOS 模拟器（Xcode Simulator）

    

  
不想插 iPhone 真机？Mac 上 Xcode 自带的模拟器也能跑 iOS 自动化——适合冒烟、快速回归。进设备池后和真机一样远程操作、跑用例（名字下方带「模拟器」小标）。

  
⚠️ 前提：Apple 芯片 Mac（M1/M2/M3/M4）+ 已装 Xcode（含至少一个 iOS 模拟器 runtime）。Intel Mac / 没装 Xcode 的跳过本节。


  
第 1 步：起一个模拟器

  
先看本机有哪些模拟器设备：

  
xcodebuild -version
xcrun simctl list devices

  
== Devices ==
-- iOS 18.0 --
    iPhone 15 Pro (5E2756F8-3B79-42A3-A66A-C01509258A07) (Shutdown)   ✅ 有就直接用

  
没有想要的机型就新建并启动（机型名可换成 iPhone 16 / 17 等）：

  
xcrun simctl create "Matrix-iOS-1" "com.apple.CoreSimulator.SimDeviceType.iPhone-15-Pro" iOS-18.0
# ↑ 会输出一串 udid（字母数字），下面 boot 用
xcrun simctl boot "把上面输出的 udid 贴这里"

  
💡 看有哪些机型可开：xcrun simctl list devicetypes；要常开多个模拟器就重复 create + boot 几次（一台 M 系 Mac 建议 4–6 个）。


  
第 2 步：准备 WDA 工程（WebDriverAgent）

  
模拟器跑自动化要经过 WDA（苹果的测试驱动）。Agent 会自动编译并拉起它，但你得先把 WDA 工程放到这台 Mac 上：

  
cd ~ && git clone https://github.com/SonicCloudOrg/sonic-ios-wda.git
# 克隆后工程路径 = ~/sonic-ios-wda/WebDriverAgent.xcodeproj

  
💡 首次跑用例时 Agent 会自动编译一次 WDA（约 1–2 分钟），之后复用缓存；Xcode 26 的编译兼容参数 Agent 已内置，无需你手动处理。


  
第 3 步：让 Agent 认识模拟器 + WDA

  
往配置文件追加一段（一条命令搞定，不用学编辑器）：

  
cat >> ~/matrix-agent/config/application-sonic-agent.yml <<'EOF'
modules:
  ios:
    wda-xcode-project-path: ~/sonic-ios-wda/WebDriverAgent.xcodeproj
    simulator:
      enabled: true
      poll-interval-seconds: 10
      fresh-instance-per-task: false
EOF

  
⚠️ 若第 4 步报「找不到 WDA 工程」，把 path 换成完整路径：先跑 cd ~/sonic-ios-wda && pwd，用输出的路径（如 /Users/tom/sonic-ios-wda/WebDriverAgent.xcodeproj）替换 ~/...。


  
第 4 步：重启 Agent 并确认

  
cd ~/matrix-agent
pkill -f "sonic-agent-.*\.jar"; sleep 2
nohup java -Dfile.encoding=utf-8 -Dspring.profiles.active=sonic-agent -jar sonic-agent-*.jar > agent.log 2>&1 & disown
sleep 10 && grep -E "Enable iOS Simulator module|server auth successful" agent.log

  
… Enable iOS Simulator module   ✅ 模拟器模块已加载
… server auth successful!       ✅ 连上服务器

  
打开平台「设备中心」，你 boot 的模拟器会以 iOS 出现（带「模拟器」小标），状态在线。


  
第 5 步：跑远程自动化

  
    
    
  1. 设备中心对模拟器点「远程控制」——能看到画面、能鼠标点按（画面走 WDA，无需 USB）。
    2. 
    
  2. 「安装」App 时选模拟器专用包（不是真机包）。
    3. 
    
  3. 写/跑用例与真机流程完全一样，选中这台模拟器下发即可。
    4. 
  

  
⚠️ 两条边界：① 模拟器只能装 simulator 构建的包（真机 arm64 IPA 装不进去）；② 支付 / 推送 / 生物识别 / 风控类用例在模拟器上行为不可信，请走真机。

  
🎉 完成！模拟器适合 冒烟 / 快速回归 / 兼容性初筛（快、零成本）；关键流程仍建议真机验证。







  
🚑
出问题了？按症状对号入座


  
Agent 连不上服务器（grep 没有 server auth successful）

    
最常见：Agent Key 填错。核对 ~/matrix-agent/config/application-sonic-agent.yml 里的 key 和网页 Agent 中心显示的完全一致（复制粘贴，别手敲）。

    
其次：服务器地址不通。验证：把浏览器打开 http://服务器地址 能进平台网页吗？能 → 是地址填错了；不能 → 找管理员（服务器或网络问题）。

    
重复启动：一台 Mac 只能跑一个 agent。检查：pgrep -fl sonic-agent 应该只有一个 java 进程。

  


  
设备详情一直转圈 / 远程控制连不上画面

    
最常见：Mac 换过 Wi-Fi、IP 变了（agent 显示在线但画面点不开）。两个命令对照：

    
ipconfig getifaddr en0          # Mac 现在的 IP
grep host ~/matrix-agent/config/application-sonic-agent.yml

    
两者不一致 → 重新生成配置（回第 3 步）改成当前 IP，或干脆改成 127.0.0.1（只自己看，一劳永逸），然后按「日常维护」重启 agent。

  


  
投屏是黑屏（页面能打开，画面全黑）

    
手机是 Android 14 及以上，而这台 agent 的投屏组件是老版本。让管理员给最新的 agent 包（已内置修复），或跑团队的补丁脚本：

    
tools/android14-scrcpy-fix/patch-agent-scrcpy.sh ~/matrix-agent --restart

    
（脚本在 matrix-agent 仓库里，找管理员拿一份放到你机器上再跑）

  


  
手机反复上线/掉线，画面时好时坏

    
① 先查数据线（最高频）：换一根好线、直插 Mac 机身、不要经过扩展坞/hub。

    
② 再查 adb 打架：如果你还装了 Homebrew 的 adb 且版本和 agent 自带的不同，两者会互相把对方踢下线。统一版本：

    
cd ~/matrix-agent/plugins && mv adb adb.orig && ln -s "$(command -v adb)" adb

    
然后按「日常维护」重启 agent。彻底方案：跑团队的 adb 升级脚本把两边都统一到 37.0.1。

  


  
手机上明明点了允许，设备列表还是没有

    
① ~/matrix-agent/plugins/adb devices 看状态：没有手机 = 线/口问题；unauthorized = 再看手机屏幕点授权；有且是 device = 等 30 秒刷新网页。

    
② 还不行，按「日常维护」重启一次 agent。

  


  
macOS 弹窗说「无法验证开发者 / 已阻止使用」

    
系统安全策略拦了自带的插件（正常现象）。「系统设置 → 隐私与安全性」往下翻，对被拦的项目点仍要打开。不要照网上说的全局关闭 Gatekeeper。

  







  
🔁
日常维护（就这 3 招）

  
重启 Agent（解决 80% 的问题）

  
cd ~/matrix-agent
pkill -f "sonic-agent-.*\.jar"; sleep 2
nohup java -Dfile.encoding=utf-8 -Dspring.profiles.active=sonic-agent -jar sonic-agent-*.jar > agent.log 2>&1 & disown
sleep 10 && grep "server auth successful" agent.log   # 出现即连上

  
看日志（排查问题先看它）

  
tail -100 ~/matrix-agent/agent.log          # 最近 100 行
grep -i error ~/matrix-agent/agent.log     # 只看报错

  
升级 Agent

  
管理员发新 zip 后：解压 → 把里面的 jar 和 plugins/ 覆盖到 ~/matrix-agent（config 别覆盖，你的配置在里面）→ 重启。或直接让管理员给完整新目录，重做第 3 步配置。
